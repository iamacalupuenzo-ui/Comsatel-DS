Uso en código

Cómo se consume un token dentro de comsatel-ds y de cualquier proyecto que la importe. Dos mecanismos: la variable CSS directa, para casi todo, y el helper de tipografía, para texto.

Color, espaciado, radio, sombra, motion

Se escribe var(--token) directo en cualquier propiedad CSS — no hace falta importar nada.

Ejemplo

Tipografía

No se escribe font-size a mano. El helper textStyle() resuelve familia, tamaño, interlineado, peso y tracking juntos, a partir de un nombre de estilo semántico (StyleName, ej. 'label/small').

Cuando el estilo depende del tamaño de un componente (sm/md/lg), se pasa por componentTypography en vez de escribir el nombre del estilo suelto — así la decisión de qué tamaño de texto usa cada tamaño de componente queda en un solo lugar. Ejemplo real de cs-badge:

La plantilla aplica el resultado con [ngStyle]="style" — el objeto que devuelve textStyle() ya son propiedades CSS camelCase listas para eso.

z-index

Nunca un número suelto. La escala es jerárquica a propósito: escribir z-index: 999 rompe el orden acordado del sistema con el próximo componente que sí use el token correcto.

Cómo se verifica

Este proyecto tiene un gate automático — no depende de que quien revisa se acuerde de mirarlo a mano.

Corre check:guidelines, check:props, check:a11y y check:examples — este último valida cada bloque de código de las guías contra la API real de la librería, así que un ejemplo con una prop que no existe falla el build antes de llegar a producción.

Lineamientos de uso

Recomendado

Usa el token semántico, incluso cuando el valor primitivo parece más directo.

color: var(--color-text-base-boldest);
Evita

No escribas el hex ni un primitivo directo: pierde el theming automático y se desincroniza el día que el token cambie.

color: #101828;
