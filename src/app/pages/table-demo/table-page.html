Table

Table presenta datos tabulares con semántica nativa y mantiene el estado en quien la consume. La búsqueda, los filtros y la paginación se componen alrededor de ella; el componente recibe las filas visibles, comunica el orden solicitado y representa con fidelidad carga, actualización y vacío.

Playground

Filtra, ordena, selecciona una unidad y alterna la paginación. El control de carga permite revisar skeleton, refetch y vacío sin simular datos en el componente.

Composición y límites

DecisiónComportamiento
OrdenamientoTable emite la columna solicitada; la aplicación ordena datos locales o solicita la nueva página al servidor. El orden reinicia la página en 1.
Búsqueda y filtrosViven arriba de la tabla y reducen las filas antes de entregarlas. El estado vacío explica si no hay datos o si no hay coincidencias.
PaginaciónEs opcional. Si se conoce el total, Pagination recibe solo page y totalPages; sin paginación Table recibe todas las filas filtradas.
DensidadTable no expone tamaños arbitrarios: conserva una densidad legible y consistente. Para información jerárquica o filas expandibles usa Table Tree, no una tabla regular colapsada.
Espacio reducidoCon minWidth la tabla conserva encabezados, celdas y relaciones; cuando no cabe, el wrapper permite desplazamiento horizontal en lugar de convertirla en tarjetas.

Accesibilidad

AspectoImplementación
SemánticaUsa elementos nativos table, caption, thead, th con scope y td. caption nombra la tabla para lectores de pantalla sin duplicar el título visual.
OrdenamientoLas columnas ordenables son botones alcanzables con Tab; Enter y Espacio funcionan de forma nativa. aria-sort anuncia el orden aplicado y el botón explica el siguiente orden.
CargaEl contenedor marca aria-busy mientras carga. Skeleton es decorativo (aria-hidden) y un estado vivo anuncia que las filas se están actualizando.
Controles externosLa búsqueda tiene label asociado; filtros y filas por página usan combobox con label. Pagination expone navegación, página actual y botones con nombre accesible.
Selección y accionesUna fila visualmente seleccionable contiene un botón con un nombre específico; no depende de un clic silencioso sobre tr.
ResponsividadEl scroll horizontal conserva el orden de lectura y evita ocultar columnas sin una alternativa equivalente.

Lineamientos de uso

Recomendado

Ofrece búsqueda y filtros antes de una tabla extensa; actualiza el estado vacío de acuerdo con el criterio aplicado.

{{ guideQuery().trim() ? 'Filtro activo' : 'Sin filtro' }}
Evita

No escondas los filtros dentro de un menú si son la vía principal para encontrar una fila. El criterio activo debe ser evidente.

Filtros ocultos
Recomendado

Ordena solo columnas comparables y expresa el orden en el encabezado. En la tabla principal prueba Unidad, Estado o Actualizado.

Ordenar por actualizado
Evita

No conviertas una columna de acciones en ordenable: sus valores no tienen un orden de negocio que ayude a encontrar información.

Recomendado

Durante la carga inicial usa skeleton con la forma de las filas; durante un refetch conserva los datos visibles y señala la actualización.

Evita

No reemplaces toda la tabla por un spinner genérico: se pierde contexto y la altura cambia de forma brusca.

Recomendado

En pantallas estrechas conserva las relaciones tabulares con scroll horizontal y un ancho mínimo explícito.

Desplaza horizontalmente para ver las columnas.
Evita

No ocultes columnas críticas ni aplastes cada fila en una tarjeta. Si hay jerarquía, utiliza Table Tree.
