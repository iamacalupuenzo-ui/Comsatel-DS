Tokens explicados

Un token es un valor de diseño con nombre: en vez de escribir #1b4079 o 16px en un componente, se escribe var(--color-background-brand-default) o var(--layout-padding-lg). El nombre describe el ROL del valor, no el valor en sí — eso es lo que permite que todo el sistema cambie de tema o de escala sin tocar componentes.

Las tres capas

Ningún token vive solo: cada uno resuelve a otro, hasta llegar a un valor primitivo. Tres capas, siempre en el mismo orden.

1. Primitivo

--font-primitive-size-micro

0.6875rem (11px)

La materia prima: un valor puro, sin significado de uso. Nunca se consume directo desde un componente.

→

2. Semántico

--font-size-label-small

= primitivo anterior

Le da un ROL al primitivo: "este tamaño es para una etiqueta chica de UI". Esta es la capa que un componente puede usar.

→

3. Componente

componentTypography.badge.sm

→ 'label/small'

Ata el token semántico a un componente y tamaño específicos, para que no se repita la decisión en cada lugar que dibuja un Badge chico.

La misma cadena aplica a color, espaciado, radio, sombra y motion — solo cambia el nombre de la familia. Ver --layout-padding-2xs … --layout-padding-6xl como ejemplo de escala semántica de espaciado, o --color-text-base-boldest como ejemplo de color.

Cómo se nombran

El nombre sigue el patrón --categoría-rol-variante. Leer el nombre alcanza para saber qué es, sin abrir tokens.css.

TokenCómo se lee
--color-text-base-subtle Color → de texto → rol "base" (neutro, no marca/peligro/éxito) → variante "subtle" (menos énfasis que "default").
--color-background-brand-default-hover Color → de fondo → rol "brand" → variante "default" → estado "hover".
--layout-padding-lg Escala de layout → padding interno → paso "lg" de la escala.
--elevation-z-index-modal Elevación → capa z-index → para qué se usa ("modal").

Cómo funciona el tema

El modo oscuro no es una versión distinta de los componentes: es el MISMO token semántico resuelto a otro valor. tokens.css define cada familia dos veces — una en :root, otra dentro de [data-theme="dark"] — con el mismo nombre en ambas.

Por eso un componente que usa var(--color-text-base-boldest) nunca necesita saber en qué tema está — el navegador resuelve el valor correcto solo. Usar el color crudo en vez del token es lo que rompe el modo oscuro.

Cuando un valor no tiene token

No todo valor visual coincide con un paso de la escala — y eso está bien, siempre que quede explícito.

SituaciónQué hacer
El valor coincide exacto con un token Se ata al token, siempre. Un número suelto que por casualidad coincide con --layout-border-thick (2px) es un hallazgo de auditoría, no una excepción válida.
El valor no coincide con ningún paso de la escala Se deja explícito con un comentario que explica por qué (ej. un diámetro de punto de 6px, o un borde de 1.5px que a 2px se vería demasiado grueso) — nunca se redondea al token más cercano cambiando el tamaño visual sin que quede documentado.

Tokens y accesibilidad

AspectoRegla
Foco visibleEl anillo de foco usa --color-border-focused en toda la librería. Nunca se quita el outline de un control ni se reemplaza por un color crudo.
ContrasteTodo par de texto y fondo cumple 4.5:1 como mínimo, y 3:1 para bordes y controles no textuales — verificado con la fórmula de luminancia relativa de WCAG, no a ojo ni comparando luminosidad HSL.
El color nunca es la única señalUn estado de peligro o de éxito lleva texto o ícono además del token de color.
Movimiento reducidoCualquier animación por token de motion (GSAP o CSS) respeta prefers-reduced-motion.
