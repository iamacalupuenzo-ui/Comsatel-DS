# Comsatel DS v0.6.0

## Resumen

Migración completa a un subpath por componente (olas 2, 3 y 4): cada componente del DS tiene su propio punto de entrada, como en Angular Material o PrimeNG.

## Cambios

- **Ola 2, hojas y utilidades**: `/format`, `/accordion`, `/avatar`, `/badge`, `/banner`, `/calendar`, `/checkbox`, `/description-list`, `/empty-state`, `/list-item`, `/progress-indicator`, `/radio`, `/skeleton`, `/stat`, `/stepper`, `/tag`, `/textarea`, `/timeline`, `/toggle` y `/tooltip`.
- **Ola 3, composiciones**: `/autocomplete`, `/card`, `/column-manager`, `/date-picker`, `/date-range-picker`, `/datetime-picker`, `/datetime-range-picker`, `/dropdown`, `/file-upload`, `/filter-bar`, `/fleet-unit-list`, `/header`, `/modal`, `/select` y `/time-picker`.
- **Ola 4, superficies**: `/map-panel`, `/map-tabs`, `/page-header`, `/pagination`, `/side-drawer`, `/spotlight`, `/tab`, `/table`, `/table-tree` y `/toast`.
- **`/dropdown`** también expone sus tokens internos (`INPUT_TOKENS`, `ITEM_TOKENS`, `hoverBgFor`) para `select` y `column-manager`; la raíz reexporta `/dropdown` con una lista explícita, así que esos tokens no son API pública.
- **`/shared`**: apoyo interno para otras entradas (`radioDotSize` y los CSS de foco y glifos de selección). La raíz no lo reexporta: no amplía la API pública.
- **Raíz**: sigue exportando los mismos 209 símbolos, pero ya no contiene código propio: el archivo raíz baja de 810 kB a 3,4 kB y solo reexporta los 57 subpaths.
- **CSS**: los `@import` hacia `shared` apuntan a su nueva carpeta; el CSS emitido es idéntico al de 0.5.0 en los 30 componentes comparados (entre ellos Checkbox, Radio, DropdownItemComponent, Select, DatePicker, Table, Toast y MapPanel). `date-picker` sigue usando el CSS de `date-range-picker` con la ruta nueva.
- **Repositorio**: `scripts/migrate-entry-points.mjs` compara la API pública antes y después de mover, se detiene ante reexports indirectos y recalcula `@import`, `styleUrl` y `templateUrl` desde la ubicación original de cada archivo y falla si alguno queda roto; `scripts/add-light-imports.mjs` agrega a las guías la línea «Import liviano» a partir de sus tablas de props.

## Impacto para consumidores

Sin cambios que rompan: cada import actual desde `@iamacalupuenzo-ui/comsatel-ds` sigue igual. Cada componente ya se puede importar por subpath; una pantalla deja de traer la librería completa cuando **ningún** import de su chunk usa la raíz.

## Medición

Sitio del DS en producción (`--stats-json`, bytes por `bytesInOutput`):

| Qué | 0.4.0 (subpaths en el shell) | 0.6.0 |
| :-- | --: | --: |
| Librería en `main` | 28.726 B | 28.726 B |
| Initial total | 530,21 kB | 530,22 kB |
| DS en chunks diferidos | 1 chunk: 589.591 B de raíz | 1 chunk: 336.880 B de raíz + 256.102 B de subpaths |

El total del DS no cambia (unos 592 kB): las páginas del sitio importan desde la raíz y la raíz reexporta cada subpath, así que el mismo chunk diferido reúne ambos. En FleetOperations no hay medición A/B en esta ola: ninguna pantalla puede dejar la raíz hasta que existan los subpaths de las olas 3 y 4.
