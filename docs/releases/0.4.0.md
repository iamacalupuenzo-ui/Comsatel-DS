# Comsatel DS v0.4.0

## Resumen

Primeros puntos de entrada secundarios: `/icons`, `/motion` e `/input`. Un consumidor que importa desde ellos carga solo esas piezas en vez de la librería entera.

## Cambios

- **Subpaths nuevos**: `@iamacalupuenzo-ui/comsatel-ds/icons` (`Icon`, `ICON_REGISTRY`, `IconName`), `/motion` (`Motion`, `PressScale`, eases y duraciones) y `/input` (`InputGroupClear`).
- **Import raíz**: sigue exportando todos los símbolos, incluidos los que ahora viven en subpaths.
- **Sitio de documentación del DS** (no forma parte del paquete): su shell importa desde `/icons` y `/motion`; la librería en el bundle inicial bajó de 626.634 a 28.726 bytes y el total inicial de 1,03 MB a 530 kB.
- **Repositorio**: el sitio, Storybook y los tests resuelven la librería por el `exports` del paquete (`build:lib` enlaza `dist/comsatel-ds` en `node_modules`), sin rutas a archivos internos.
- **Chequeos**: `check:entry-imports` impide que un subpath importe la raíz (evita el ciclo y la carga completa); `verify:package` comprueba antes de publicar que el tarball trae cada export con su código y tipos.

## Impacto para consumidores

Sin cambios que rompan: cada import actual desde `@iamacalupuenzo-ui/comsatel-ds` sigue funcionando igual. Para cargar menos, importa desde el subpath; el ahorro solo aparece si ningún import del mismo chunk usa la raíz. Detalle en «Importar desde un subpath» de `docs/consumer-angular.md`.

## Verificación

- `npm run build:lib` y `npm run verify:package`
- `npm run check:docs` y `npm run test:ci`
- `npm run build-storybook`
